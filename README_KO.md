# 코레일 공식 검색화면 감시 v5 — Railway + Telegram

이 버전은 **v4가 최초 검색화면에서 `#labelstart`를 찾지 못해 실패한 문제를 수정한 시험 버전**입니다. 아직 Railway에서의 실제 검색 성공을 확인한 버전은 아닙니다.

## 1. 감시 조건 (v4와 동일)

| 항목 | 설정 |
|---|---|
| 출발일 | **2026년 10월 24일 (토)**, **00:00부터** |
| 출발역 | **목포** |
| 도착역 | 기준 **서울**, **인접역 보기 포함** 및 **서울·용산 - 수서 함께 보기 포함** |
| 인원 | 성인 1명 |
| 열차 | KTX / KTX-산천, **더보기 없이 첫 화면 최대 10편** |
| 알림 | 일반실·특실 운임 금액 또는 **예약대기**가 새로 나타날 때 Telegram |
| 제외 | 입석+좌석, 입석/자유석, 매진, **456편(목포 11:43→서울)** |
| 간격 | **20~30초 랜덤**, 브라우저 F5 방식 |
| 종료 | **2026-10-25 00:00 KST** |

예약·결제·좌석 확보·로그인·CAPTCHA/접속제어 우회는 하지 않습니다. URL `https://www.korail.com/ticket/search/list`는 검색 조건을 인코딩하지 않으므로 최초 검색은 `/ticket/search/general`에서 실제 공식 화면을 통해 수행합니다.

## 2. v4 대비 변경사항

사용자가 2026년 10월 17일에 제공한 `korail_general.txt`의 **JavaScript 실행 후 렌더링된 실제 검색 화면**을 분석하여 다음 요소를 확인했습니다.

| 기능 | `/ticket/search/general`의 실제 요소 |
|---|---|
| 출발역 | `input[name="txtGoStart"]` + 주변 `.start a.btn_pop-open` |
| 도착역 | `input[name="txtGoEnd"]` + 주변 `.end a.btn_pop-open` |
| 날짜 | `#startDate` + `a[title="출발일"]` |
| 인원 | `.tab-tck.type_by a[title="인원"]` |
| 인접역 | `input[name="adjStnScdlOfrFlg"][value="Y"]` (`#option01`) |
| 서울/용산/수서 함께 보기 | `input[name="adjStnScdlOfrFlg2"][value="Y"]` (`#option05`) |
| 검색 | `.tab-tck.type_by button.btn_lookup` |

v4는 **검색 결과**(`/list`)의 입력 요소 `#labelstart`, `#labelend`, `#labelple`와 체크박스 구조를 **최초 검색 화면**(`/general`)에도 잘못 적용했습니다. 이번 버전은 `general_form.py`에서 최초 검색만 별도로 처리합니다.

날짜를 선택할 때 **00:00 시간**까지 검증합니다. 검색 시각이 늦은 시간으로 설정되어 오전 KTX가 누락되는 문제를 방지하려는 목적입니다. 검색 결과에 진입한 후에는 이전에 받은 `korail_elements.html`을 기준으로 검증한 `li.tckList` 분석기를 그대로 사용합니다.

**아직 확인되지 않은 부분:** 두 파일은 팝업을 열기 *전* 상태이므로, 출발역 선택 팝업·날짜/시간 선택 팝업의 HTML은 들어 있지 않습니다. v5는 보이는 UI를 정상적으로 클릭하려고 시도하지만, 팝업 구조가 예상과 다르면 실패할 수 있습니다. 강제로 내부 React 상태를 변경하거나 인증/접속 제한을 우회하지 않습니다.

## 3. Railway 설치/교체

기존 v4가 실패 중이라면 **같은 GitHub Repository의 파일들을 v5 ZIP 내부 파일로 교체하여 Commit**하면 됩니다. 이전 v4와 함께 동시에 실행하지 마세요.

1. ZIP 압축을 풀고 내부 파일(`browser.py`, `general_form.py`, `parse_trains.py`, `watcher.py`, `Dockerfile`, `requirements.txt`, `railway.json`)을 GitHub 저장소 루트에 업로드/덮어씁니다.
2. Railway 연결이 유지돼 있다면 새 Commit에 따라 재배포됩니다. 로그의 버전이 `v5-browser-general-form`인지 확인하세요.
3. 기존 텔레그램 환경변수는 그대로 재사용합니다.

| 변수 | 필수 여부 및 값 |
|---|---|
| `TELEGRAM_BOT_TOKEN` | 필수 · 기존 값 |
| `TELEGRAM_CHAT_ID` | 필수 · 기존 값 |
| `POLL_MIN_SECONDS` | 선택 · 기본 `20` |
| `POLL_MAX_SECONDS` | 선택 · 기본 `30` |
| `REFRESH_MODE` | 선택 · 기본 `reload` (F5) |
| `HEARTBEAT_MINUTES` | 선택 · 기본 `60` |
| `STATE_FILE` | 선택 · 기본 `korail_web_v5_state.json` |

Dockerfile은 `general_form.py`를 새로 복사하므로 파일을 빠뜨리지 않아야 합니다.

### 로그 확인 요령

- `브라우저 최초 검색 검증 성공`과 `#1 검증성공 KTX=10`이 나타나면 초기 검색+열차 판독의 실제 배포 검증을 통과한 것입니다.
- `검색 조건 자동 설정 실패 ... 출발역 목포 선택`이면 **출발역 팝업** 단계에서 실패한 것입니다.
- `... 달력에서 2026-10-24 선택 실패`이면 **달력 날짜** 단계입니다.
- `... 출발시각 00:00 설정 실패`이면 **시간 선택** 단계입니다.
- `... 결과 검증 실패`이면 조회 결과에 표시된 날짜/역/필터/좌석 목록을 다시 확인해야 합니다.

팝업에서 실패한 경우, Railway 로그의 **최초 실패 줄과 뒤따르는 진단 줄**을 보내주세요. 필요하다면 실제 PC에서 팝업을 클릭해서 띄운 상태의 스크린샷이나 Elements HTML만 추가로 요청할 수 있습니다. 검색 결과 전체 파일은 다시 보내지 않아도 됩니다.

## 4. 보안·안전장치

- HTTP 403/429, CAPTCHA, NetFunnel 대기 화면 등을 만나면 우회 없이 5~10분 백오프 후 3회 연속 제한 시 감시 중단하고 Telegram으로 알립니다.
- 최초 검색 UI 설정 오류는 90초 대기하며 3번 실패하면 경고 후 중단합니다.
- 일반 읽기/로딩 오류는 60초부터 지수형으로 간격을 늘리고, 연속 3회면 브라우저를 다시 시작합니다.
- 부정확한 날짜/역/인원/필터, 조회 결과 없음, 알 수 없는 좌석 상태는 **매진으로 오인하지 않으며** 예약 가능 알림을 보내지 않습니다.
- 동일 예약 가능/예약대기 상태의 중복 알림은 제한하고, 매진되었다가 다시 열리면 재알림합니다.
- 10월 25일 00:00 KST 이후 자동 종료하며, 이미 지난 뒤 컨테이너가 시작되면 즉시 종료합니다.

**20~30초 F5도 코레일 측에 많은 요청을 발생시킬 수 있습니다.** 차단 임계치는 불명이며, URL 1회 새로고침이 HTTP 요청 1회라는 뜻은 아닙니다. 오류나 제한이 발생하면 주기를 늘리거나 중단하세요. 다른 IP나 계정으로 제한을 우회하는 기능은 제공하지 않습니다.

## 5. 오프라인 테스트

```bash
pip install -r requirements.txt
python -m unittest discover -s tests -v
```

- 기존 열차 판독 테스트 18개
- 실제 `/general` HTML을 축약해 만든 검색 폼 구조 테스트 2개
- 모의 팝업을 통한 브라우저 선택 순서 테스트 1개

총 **21개 테스트**를 통과했습니다. 이는 **실제 코레일 서버에 접속한 테스트가 아닙니다.** 실제 검색 성공은 Railway 배포 로그로 확인해야 합니다.

여정 페이지: https://www.korail.com/ticket/search/general
